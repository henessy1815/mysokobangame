# 소코반 : 동굴의 상자

`02-prd.md`를 구현한 React 소코반 게임입니다. 동굴을 배경으로 상자를 밀어 표식 위에
올려놓는 10단계 논리 퍼즐이고, 버스·지하철에서 짧게 끊어 즐기는 상황을 기준으로 만들었습니다.

## 실행

```bash
npm install
npm run dev        # 개발 서버
npm run build      # 프로덕션 빌드 (dist/)
npm run preview    # 빌드 결과 미리보기

npm run validate:levels          # 10단계 전부 클리어 가능한지 검증
npm run validate:levels -- --paths   # 각 단계의 최단 해답까지 출력
```

의존성은 React와 Vite뿐입니다. 이미지·폰트·사운드 파일을 하나도 받지 않아서
(스프라이트는 인라인 SVG, 효과음은 WebAudio 합성) 네트워크가 끊기는 지하철에서도
한 번 연 뒤에는 그대로 굴러갑니다.

## 조작

| 입력 | 동작 |
| --- | --- |
| 스와이프 | 해당 방향으로 한 칸. 손가락을 떼지 않고 계속 끌면 연달아 이동합니다. |
| 화면 하단 방향 버튼 | 한 칸 이동. 길게 누르면 반복 이동. |
| 방향키 · WASD | 이동 |
| `Z` | 되돌리기 |
| `R` | 다시하기 |
| `Esc` | 단계 선택으로 나가기 |

이동할 때마다 10% 확률로 빈 칸에 사과가 떨어집니다. 그 칸을 밟으면 상단의 사과 수가
1 올라갑니다. 퍼즐 규칙과는 무관한 덤입니다.

## 구조

```
src/
  game/
    engine.js     소코반 규칙 (순수 함수, React 비의존 → Node 검증 스크립트와 공유)
    levels.js     10단계 레벨 데이터 (XSB 표기)
    solver.js     최적해 탐색기 — 앱 번들에는 포함되지 않고 검증에만 쓰입니다
    storage.js    진행 상황 저장/복원 (localStorage)
    audio.js      WebAudio 효과음 + 진동
  hooks/
    useSokoban.js          한 판의 상태와 일회성 이벤트
    useSwipe.js            스와이프 방향 입력
    useKeyboardControls.js 키보드 입력
    useElementSize.js      격자 크기 계산용 요소 실측
  components/     화면과 스프라이트
  styles/         토큰 · 화면 레이아웃 · 격자
scripts/
  validate-levels.mjs   레벨 검증 (아래 참고)
```

## 설계에서 중요한 결정들

### 부드러운 이동은 transform 트랜지션 하나로

바닥·벽·목표는 CSS 그리드에 한 번 깔고 끝냅니다. 움직이는 것은 플레이어와 상자뿐이라,
각자 절대 위치 요소로 띄워 두고 `transform: translate3d(...)`에 150ms `ease-out`
트랜지션만 겁니다. 레이아웃을 건드리지 않으므로 합성 단계에서만 처리되고, 한 수마다
격자를 다시 그릴 일이 없습니다.

상자의 React key는 배열 인덱스, 즉 상자의 고유 ID입니다. 밀려도 같은 DOM 노드가
유지되어야 트랜지션이 이어집니다.

### 입력은 큐에 쌓지 않고 즉시 반영합니다

PRD는 "이동 중 다음 입력은 큐에 쌓아 끊김 없이 연결"을 적어 두었습니다. 구현은
큐 대신 **상태를 즉시 갱신하고 CSS 트랜지션이 목표 지점을 다시 겨냥하게** 했습니다.
결과적으로 입력이 버려지지도, 애니메이션을 기다리느라 밀리지도 않습니다. 빠르게
연타하면 스프라이트가 약간 뒤따라오며 부드럽게 따라잡습니다. PRD가 큐로 막으려던
것(입력 유실·지연)을 더 단순한 방법으로 달성하므로 이 형태를 택했습니다.

### 되돌리기는 이동 수를 되돌립니다

되돌리기를 눌렀는데 카운터가 올라가면 손해 본 것처럼 느껴져 결국 재시작을 택하게 됩니다.
그래서 `undo`는 이동 수와 밀기 수를 함께 되돌립니다. 기록은 최대 400수까지 남고,
저장된 판에도 함께 실려서 앱을 껐다 켜도 되돌리기가 살아 있습니다.

### 진행 상황은 한 수마다, 앱이 닫힐 때 한 번 더

클리어 기록뿐 아니라 **진행 중이던 판 전체**(플레이어 위치, 상자 배치, 이동 수, 되돌리기
기록)를 localStorage에 넣습니다. 한 수마다 저장하되 250ms 모았다 쓰고, `pagehide`와
`visibilitychange`에서 즉시 비웁니다. 지하철에서 앱을 그냥 덮어 버리는 쪽이 기본 상황이기
때문입니다.

저장된 값은 사용자가 손댔거나 예전 버전일 수 있으므로 읽을 때 형태를 일일이 확인하고,
레벨 레이아웃과 아귀가 맞지 않으면 버립니다. 시크릿 모드처럼 저장소가 막힌 환경에서는
읽기·쓰기 실패를 조용히 삼키고 게임은 그대로 진행됩니다.

### 가독성이 분위기보다 먼저

동굴 분위기를 위해 벽과 바닥을 비슷한 명도로 두면, 횃불빛과 비네트가 얹히는 순간
구분이 뭉개집니다. 한눈에 길을 읽어야 하는 퍼즐에서는 치명적이라 **벽을 바닥보다 확실히
밝게** 잡았습니다. 챕터(동굴 깊이)마다 색조는 바뀌지만 이 명도 관계는 세 챕터 모두
유지됩니다.

같은 이유로 상태를 색으로만 구분하지 않습니다. 목표에 올라간 상자는 색이 밝아지는 동시에
판자 무늬가 X에서 마름모로 바뀌고 테두리가 달라집니다. 잠긴 단계에는 자물쇠, 클리어한
단계에는 체크 아이콘이 붙습니다.

### 사과는 퍼즐 바깥의 덤

한 칸 움직일 때마다 10% 확률로 빈 바닥 한 곳에 사과가 떨어지고, 그 칸을 밟으면
상단의 사과 수가 1 올라갑니다. 규칙은 퍼즐에 전혀 간섭하지 않습니다. 클리어 조건도
이동 수 기록도 그대로이고, 사과를 하나도 줍지 않아도 모든 단계를 깰 수 있습니다.
가는 길에 잠깐 눈이 가는 정도의 덤으로 두려던 것이라, 다음 세 가지를 지켰습니다.

- **목표 지점과 상자 위에는 떨어지지 않습니다.** 퍼즐을 읽는 데 꼭 필요한 표식을
  사과가 가리면 안 되고, 상자 밑에 깔린 사과는 보이지도 줍지도 못합니다.
- **방금 선 칸에도 떨어지지 않습니다.** 떨어지자마자 주워지면 떨어지는 연출을 볼
  새가 없고, 한 수에 줍기와 떨어뜨리기가 겹쳐 되돌리기 기록이 지저분해집니다.
- **되돌리기가 사과까지 되돌립니다.** 되돌린 수에서 떨어진 사과는 거두고, 주웠던
  사과는 제자리로 돌아오며 개수도 함께 내려갑니다. 벽에 막힌 수는 이동이 아니므로
  사과도 떨어지지 않습니다.

난수는 엔진 바깥에서 주입합니다(`move(board, state, dir, { rng })`). `rng`를 넘기지
않으면 사과 규칙 자체가 돌지 않기 때문에, 같은 엔진을 쓰는 레벨 검증 스크립트와
해답 탐색은 예전과 똑같이 결정적으로 동작합니다.

### 소리와 진동은 기본 꺼짐

대중교통에서 켜자마자 소리가 나는 쪽이 잘못이라고 보고 둘 다 기본값을 꺼짐으로 두었습니다.
설정에서 켤 수 있습니다.

### 배터리

렌더링 루프가 따로 없고 입력이 있을 때만 다시 그립니다. 유일하게 계속 도는 횃불 깜빡임과
표식 맥동 애니메이션은 화면이 가려지면 `animation-play-state: paused`로 멈춥니다.

## 레벨 검증

PRD 출시 체크리스트의 "1~10단계 전부 클리어 가능 검증"을 `npm run validate:levels`로
자동화했습니다. 레벨마다 네 가지를 봅니다.

1. **구조** — 상자와 목표 개수 일치, 플레이어 존재, 바깥으로 새지 않는 벽, 도달 가능한 배치
2. **해답 존재** — `solver.js`가 최소 이동 수를 구합니다
3. **리플레이** — 찾아낸 해답을 `engine.js`의 규칙으로 되돌려 실행해 실제로 클리어되는지 확인합니다.
   탐색기와 게임 엔진이 서로를 교차 검증하게 만드는 장치입니다
4. **par 대조** — `levels.js`에 적힌 par가 실제 최소 이동 수와 같은지 확인합니다

탐색기는 이동 한 칸이 아니라 **밀기**를 간선으로 삼는 그래프에서 A*를 돌립니다.
간선 비용은 "밀기 직전 칸까지 걸어가는 최단 거리 + 1"이고, 밀기 사이의 걸음은 상자 배치를
바꾸지 않으므로 언제나 최단 경로로 대체할 수 있습니다. 따라서 이 그래프의 최단 경로가
곧 실제 최소 이동 수입니다. 어떤 목표로도 보낼 수 없는 사장 칸과 2x2 교착을 미리 쳐내
상태 폭발을 막습니다.

현재 검증 결과:

| 단계 | 제목 | 상자 | 최소 이동 | 밀기 |
| ---: | --- | ---: | ---: | ---: |
| 1 | 첫 번째 궤짝 | 1 | 2 | 2 |
| 2 | 모퉁이 돌기 | 1 | 6 | 3 |
| 3 | 두 개의 표식 | 2 | 16 | 6 |
| 4 | 갈라진 암벽 | 2 | 23 | 10 |
| 5 | 무너진 서쪽 통로 | 3 | 26 | 8 |
| 6 | 천장의 틈 | 3 | 32 | 13 |

## 레벨 추가하기

`src/game/levels.js`에 XSB 표기로 레이아웃을 적고 `npm run validate:levels`를 돌립니다.
검증기가 출력한 최소 이동 수를 `par`에 적으면 됩니다. par는 손으로 고치지 마세요.

```
#  벽        (공백)  바닥      .  목표
$  상자       *  목표 위 상자   @  플레이어     +  목표 위 플레이어
```

## PRD에서 다루지 않은 것

PRD의 "범위 밖"을 그대로 지켰습니다. 멀티플레이, 계정·클라우드 동기화, 광고·결제,
11단계 이상, 레벨 에디터, 제한 시간 같은 압박 요소는 없습니다.
